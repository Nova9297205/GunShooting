# CO-OP SHOOTER 2D（GunShooting）

> 🧟 ゾンビサバイバル＆拠点防衛ゲーム **DEAD NIGHTS 2D** は [`zombie/`](zombie/README.md) にあります（GitHub Pages では `/zombie/` で公開）。

ブラウザで動く 2〜3人協力（PvE）見下ろし型シューティングのプロトタイプです。
専用ゲームサーバー不要で、PeerJS（WebRTC）によるホスト・ゲスト方式の P2P マルチプレイに対応しています。

- Vite + TypeScript / HTML5 Canvas（画像ファイル不使用・全てコード描画）
- PeerJS によるホスト権威型同期（ホストが全計算 → 30Hz でスナップショット配信）
- ゲストは自機のクライアント側予測＋リコンシリエーション、他者・敵は線形補間

## セットアップ

```bash
npm install
npm run dev      # 開発サーバー（http://localhost:5173）
npm run build    # 型チェック + 本番ビルド（dist/）
npm run preview  # ビルド結果の確認
```

## 操作

| 操作 | キー |
| --- | --- |
| 移動（8方向） | W / A / S / D（矢印キーも可） |
| 照準 | マウス |
| 射撃（長押し連射） | 左クリック |
| ダッシュ（クールタイム 1.2 秒） | Shift（Space も可） |
| 蘇生 | ダウンした味方の近くで E を 2.5 秒長押し |

## ゲームルール

- ウェーブ制。ウェーブが進むと敵の数・HP・速度が増加。ウェーブクリアで生存者の HP +25、戦闘不能者は復帰。
- HP が 0 になるとダウン（移動が極端に遅くなり射撃不可、30 秒のカウントダウン）。味方が E 長押しで HP 50% で蘇生。
  カウントダウンが尽きると戦闘不能になり、次のウェーブ開始時に復帰。
- 全員がダウン／戦闘不能になるとゲームオーバー → リザルト（到達ウェーブ・撃破数）→ ロビーへ。
- 敵
  - チェイサー（赤い三角形）: 最寄りのプレイヤーへ体当たり
  - シューター（紫のひし形）: 距離を保ちつつ赤いエネルギー弾を射撃（Wave 2〜）
  - タンク（オレンジの六角形）: 遅いが高耐久。撃破時に周囲の敵を吹き飛ばす小爆発（Wave 3〜）
- 遮蔽物はプレイヤー・敵どちらの弾も防ぎます。

## ローカルでのマルチプレイ動作確認（PC 1 台）

1. `npm run dev` を起動する。
2. ブラウザで `http://localhost:5173` を 2〜3 個開く。
   - **推奨: タブではなく別ウィンドウにして横に並べる。** 非表示タブはブラウザがタイマーや描画を間引くため、
     裏にあるタブのプレイヤーは止まって見えます（ホストのタブが裏にあっても、ゲストの入力受信をトリガーに
     シミュレーションが進むようにしてあるので、ゲームは止まりません）。
3. 1 つ目のウィンドウで「部屋を作る（ホスト）」→ 表示された 6 桁のルーム ID を「コピー」。
4. 2 つ目・3 つ目のウィンドウでルーム ID を貼り付けて「部屋に参加する（ゲスト）」。
   - `http://localhost:5173/?room=ABC123` のように URL に付けると入力欄に自動で入ります。
5. ロビーに P1〜P3 が揃ったらホストが「ゲーム開始」。
6. 4 人目の参加は「満員」、ゲーム中の参加は「進行中」として拒否されます。

### シグナリングサーバーについて

接続の仲介（シグナリング）には、デフォルトで PeerJS の公開サーバー（0.peerjs.com）を使うため、
インターネット接続が必要です。接続が不安定な場合やオフラインで試したい場合は、ローカルに PeerServer を立てられます。

```bash
# 別ターミナルで（初回のみパッケージをダウンロードします）
npx -p peer peerjs --port 9000

# .env.local を作成
cp .env.example .env.local
# VITE_PEER_HOST=127.0.0.1 / VITE_PEER_PORT=9000 のコメントを外す
npm run dev
```

> 環境によって `::` へのバインドに失敗する場合は `npx -p peer peerjs --port 9000 --host 127.0.0.1` を使ってください。

### 別の PC から参加する場合

`npm run dev` は `--host` 付きで起動するので、同一 LAN 内の別 PC から `http://<ホストPCのIP>:5173` でアクセスできます。
（ローカル PeerServer を使う場合は `VITE_PEER_HOST` をホスト PC の IP にしてください。）

## ディレクトリ構成

```
src/
  main.ts                    エントリーポイント・UI 制御（タイトル / ロビー / リザルト）
  types.ts                   プレイヤー・敵・弾・スナップショット・通信パケットの型
  style.css                  UI スタイル
  game/
    Engine.ts                HostSimulation：ホスト権威のゲーム計算（入力適用・弾・敵AI・判定・HP・ウェーブ）
    GameSession.ts           ゲームループ：モード別の更新、スナップショット送信、ゲストの予測・補間
    Renderer.ts              Canvas 描画：カメラ、胴体＋タレットのパーツアニメ、リコイル、エフェクト、HUD、ミニマップ
    Effects.ts               パーティクル・ダメージ数値・画面揺れ・バナー
    Input.ts                 キーボード・マウス入力
    physics.ts               当たり判定・移動（ホストとゲスト予測で共通の stepMovement）
    constants.ts             パラメータ・マップ定義
  network/
    NetworkManager.ts        PeerJS：ルーム作成、最大 2 ゲスト接続、入力送信、スナップショット配信
```

## 同期の仕組み（概要）

- **ホスト**: 60Hz 固定ステップで `HostSimulation` を実行。ゲストの入力は届いた順に各入力の `dt` で移動を積分し、
  処理済みの入力番号（`ack`）をスナップショットに含めて 2 tick ごと（約 33ms）に配信。
  パーティクル等の演出は「イベント」としてスナップショットに同梱。
- **ゲスト**: 毎フレーム入力をホストへ送信しつつ、同じ `stepMovement` で自機を即時に動かす（クライアント側予測）。
  スナップショット受信時はホストの確定位置から未処理入力を再適用し、ズレは見た目上なめらかに吸収。
  射撃も見た目の弾・マズルフラッシュ・リコイルを即時表示（ダメージ判定はホスト）。
  他プレイヤー・敵・弾は 100ms 遅延でスナップショット間を線形補間して描画。
